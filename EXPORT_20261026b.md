# October 26 afternoon/evening export scope

This export curates existing experiments and writes an aggregate update and
retrospective. No challenge submission, dataset download, model run or public
posting is part of the publication job. Historical `official_*` file names and
references to "official runs" mean local execution of cell-eval2 0.18.0 unless
explicitly identified as submitted validation scores in OFFICIAL_SCORES.md.

Included:

- calib3_1026, signaudit_1026 and dm_1026: reports, analysis scripts and small
  numerical summaries.
- h2h2_1026: campaign report and registered amendments; R9 build, scorer, generated
  scoring functions and gate; immediate scoring/runtime dependencies; result
  Markdown. The preceding morning export's analysis/runtime sources are retained.
- h2h2_1026/scratch/mse_instr: report, details, method notes, scripts and two CSV
  tables. This narrowly selected historical scratch directory contains source and
  aggregate tables only.
- bio_gap_1026, shared_resp, align and loco_map: reports, methods, prior-art notes,
  scripts and selected result summaries/certificates, each below 1 MB. Per-target
  rows report diagnostic metrics or fitting choices, not cell-level data.
- decisions/consult_1026_amp: briefs, Fable/Opus/Astra responses for rounds 5–12,
  and the decision history. These are AI advisor outputs, not private messages
  from other people. Earlier answer texts and operational runner scripts are
  omitted. The decision history summarizes earlier rounds.
- competitors/IDEAS-2026-10-26.md: dated public-source review, without its raw
  source payloads. Its hypotheses are historical; subsequent tests refuted several.

Excluded: input datasets, prediction and model arrays, fitted coefficient arrays,
cell matrices, raw competitor payloads, process listings, operational status logs,
machine completion snapshots, error logs and all files over 5 MB. In particular,
the align inner-objective table exceeds 20 MB and is not exported. Small result
JSON files with "fits" in their names contain fit diagnostics/source-exclusion
metadata, not learned weight matrices. No publication input was taken from
personal knowledge or handoff directories.

Paths rooted in the private workbench become repository-relative references.
Interpreter examples use `python` from an independently prepared environment;
installed-library references use `.venv/…`. The calibration script discovers the
repository root from its own location. Spaces around NumPy matrix products avoid
email-detector false positives. Machine-specific scheduling details are removed
from the curated decision history. Numerical formulas and acceptance outcomes
are preserved, including mistaken premises and their subsequent corrections.

Historical receipts contain source/input hashes from their original runs. These
are provenance records, **not attestations for edited publication sources**. Missing
inputs, source pins and snapshots must be regenerated through an audited preparation
step. Do not bypass a failed provenance assertion. R9 requires private-run-style
prepared references, banks, confidence arrays, predecessor modules and scoring
receipts; the biology analyses require regenerated frozen inference and source
banks. These dependencies are deliberately absent, and the full campaigns were
not rerun for this export. Reproduction commands in historical reports describe
the original prepared workbench, not a clean-checkout quick start.

`tools/published_result_files.txt` enumerates the only allowed CSV/JSON exports;
Git ignore exceptions use the same exact paths. The source checker retains its
privacy/credential checks and enforces the task's 5 MB cap, with a stricter
1 MB cap on curated result files. All syntax checks use the project's reference
Python 3.12 environment; the older system interpreter does not support every
syntax form in the existing source tree.

Regenerate the source manifest with:

```sh
nice -n 10 python tools/update_source_manifest.py
nice -n 10 python tools/check_export.py
gitleaks dir . --no-banner --redact
```

The manifest uses the prior export's sorted SHA-256 procedure and excludes Git
metadata, PUBLISH_CHECK.md and itself. Verification results are recorded in
[PUBLISH_CHECK.md](PUBLISH_CHECK.md); the owner receives a separate local file
inventory for review. Nothing is staged, committed or pushed by this job.
