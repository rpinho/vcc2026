This job measures response-vector error on the 168 training H1 targets, and never uses the 79 reference outcomes for fitting, model selection, annotation, or scoring. All output is local to this directory. No data acquisition, package construction, upload, submission, GPU, cloud, commit, or source-bank edit occurs.

`reconstruct.py` extracts the frozen numerical definitions with AST, avoiding predecessor runtime imports that write outside this job. It executes the exact streamed `Sources.features` pathway and three H1-excluded `model_billmB/checkpoints/H1` networks, then the exact 0.3 unit-direction blend with the original pooled-response norm. The result is bitwise identical to all 79 existing frozen predictions; these are predictions and legal input controls, not reference treated outcomes. Pin hashes are in `results/provenance.json`.

The frozen predictor has no fitted H1 response labels. Its prediction is therefore identical in every destination-target LOO fold. This is destination-label LOO for a same-target cross-context transfer predictor; it is not a claim that those gene identities were absent from all other source screens. Every newly fitted H1 calibration leaves out the evaluated target. H1 source rows, both cached and full, remain excluded from frozen features and weights. Essentiality and source knockdown predictors come only from external-source metadata/responses. Observed H1 knockdown and response-strength strata are descriptive, never inference inputs.

The truth is the existing `manifold_1026/inputs/data/H1_full.npz`: 168 targets, a 18,533-gene canonical axis, and 18,077 measured genes. Its response is natural-log `log1p(50000 * pooled molecule probability)` minus global NTC, explicitly not batch matched. Genes are aligned by symbol to the frozen H1 scorer axis. This differs from log of arithmetic mean CPM, and from mean single-cell log expression.

`render_bulk.py` reads only the 3,200 legal input-control rows from the frozen task and recreates its 400-cell, four-control-pool template. It runs the unchanged B0 `mean_counts` IPF, randomized row rounding and exact integer column repair, with the original target seed. Only log-normalized group column totals are retained. The v9 layout preserves those totals, so running its DE/layout machinery cannot change this pseudobulk. It does not access the forbidden DE cache or the frozen package. This verifies a count-rendered B0 baseline, without packaging or retaining count matrices. Proposed fixes use the declared continuous clipped/renormalized probability projection; their final rendered metrics remain untested.

The primary squared-error diagnostic excludes each row's own target gene; it includes every other measured output gene. For target i, E_i = ||P_i-Y_i||² / ||Y_i||², cosine = dot(P_i,Y_i)/(||P_i||||Y_i||), and a_i = dot(P_i,Y_i)/||P_i||². `results/per_target.csv` records all 168 values plus prediction/truth norms. The aggregate E is a ratio of sums, while `macro_relative_error` averages E_i; these answer different questions. Weak responses can dominate the latter while contributing little absolute error. Error mass means the stratum's sum of SSE divided by total SSE. Family-presence strata overlap and must not be summed.

The exact orthogonal decomposition is direction = ||Y||²-dot(P,Y)²/||P||² and magnitude = ||P||²(1-a)². Their sum equals SSE. Negative best scalars are reported honestly; the diagnostic nonnegative scalar oracle uses max(a,0), so it can have a slightly smaller gain than the unconstrained decomposition's magnitude share. The oracle is a ceiling, not a learned predictor or a new-source forecast. Independent long-double recomputation covers all rows, and exact rational arithmetic verifies full-coordinate identities for three targets. Native installed `cell_eval2.metrics.discrimination.discrimination_score` independently reproduces PDS with n-1 normalization, panel-wide target-gene exclusion and midrank ties. This is PDS on this retained training pseudobulk axis, not a complete count/DE six-metric evaluation.

Essentiality is membership in the Replogle K562 essential screen, a useful growth-essential gene-set annotation; the complement is not proof of H1 nonessentiality. `results/training_metadata.json` says this explicitly. The observed H1 knockdown is recovered from the target gene's response and control probability; source knockdown is the median corresponding reduction across available eligible donor rows. Source and recipient knockdown are not interchangeable.

Exact training168 Wilcoxon `n_conf` is unavailable. Full H1 cells were deleted by the earlier acquisition job; the local `H1.h5ad` is only a 20,000-cell slice, and the full retained H1 summaries contain molecule sums, CPM sums and squared CPM sums, not cell ranks. Two moments do not identify Wilcoxon p-values. No download is allowed. Consequently `n_conf_exact` is missing for all 168 rows. A separately named `n_conf_MOMENT_PROXY` performs a two-sample normal test from full arithmetic-CPM moments, followed by per-target BH at 0.05; it excludes the own gene. Its <10, 10–999, >=1000 bins are a sensitivity diagnostic only, not the requested exact significance strata or a response-size predictor. Those exact strata remain unresolved; essential-screen membership likewise does not establish H1-specific fitness.

`analyze.py` tests a fixed global scalar, scalars by essential-screen membership and source-knockdown bins, a four-feature scalar ridge (ridge strength 10), a LOO residual-mean correction, a mean-only negative control, and a seven-family residual ridge. The scalar objective is total squared error, not the macro target-normalized error. Every scalar, normalizer and response residual uses the other 167 targets. Family coefficients use per-target donor residuals, with absent families represented as zero residual from B0; penalty equals the average Gram diagonal. No hyperparameter is chosen from the 79 outcomes. The source-family oracle chooses the best available family after seeing truth and is explicitly nondeployable. Bootstrap intervals condition on reused fitted H1 models and are exploratory, without multiplicity correction or a new-cell-line guarantee.

Public SLIM/rank-10 cores are extracted unchanged from the earlier source-only adapters. They exclude all H1 sources. The logCP10k output is inverted against the legal pooled destination control, then mapped to the logCP50k bulk comparator. This is an explicit bulk-channel adaptation of the existing adapter, not a claim to reproduce a paper's benchmark or arithmetic-CPM head. Source read and solve times, missing embeddings and normal-equation residuals are retained. Their smaller SSE mostly reflects smaller predictions; their PDS regression rules them out as replacements.

`inventory.py` reads existing full target/count metadata, applies >=30 source cells where available, and separates overlap, newly covered targets in the union, and new rows within a source family. HipSci and LINCS retained tables were previously restricted to the 2026 validation panel, so their training168 counts are lower bounds, not complete inventories. Their unknown remainder is not silently called missing. CD4, Replogle and Nadig are already in B0; full CD4 offers additional within-family coverage rather than a previously absent study. No metadata is mistaken for measured usable response values. The whole error mass on a newly covered target is a perfect-replacement ceiling; unknown context-transfer benefit has no defensible measured point forecast.

The CPU benchmark runs the exact 28,551,269-parameter network, batch64, MSE+contrastive loss, gradient clipping and AdamW, with actual feature-array gathering, 10 warmup and 100 measured steps. It measures one worker and two concurrent independent one-thread workers. Every BLAS pool and Torch numerical worker has one thread. Commands request `nice -n 10`; inherited effective priority is 20, and a self-process attempt to set 10 is denied by macOS. Times therefore describe actual nice20 execution, not a falsely certified nice10 run. Nine-fit estimates include the last unpaired fit, but exclude source-cache creation, validation/checkpoints and sustained-load variation. The old 16.09h was a dated short-run projection, not a fixed hardware fact. Already returned trained weights make reconstruction unnecessary for this diagnostic.

All gains in this job are plain squared pseudobulk-distance changes. They are not normalized, jackknife-corrected/capped official MSE. In particular shrinking P can sharply reduce the centered across-target budget B, forfeiting scorer correction. `results/verification.json` records that budget ratio; `vcc_mse_instr_1026` must resolve its effect. Bad absolute vector error with high retrieval PDS establishes a response-calibration/direction problem; it does not establish that packaging/dispersion explains none of the official score gap.

Reproduce sequentially from this directory with the shared venv (all scripts impose one BLAS thread and confine writes):

```sh
nice -n 10 python -B reconstruct.py
nice -n 10 python -B render_bulk.py
nice -n 10 python -B analyze.py
nice -n 10 python -B inventory.py
nice -n 10 python -B cpu_baselines.py
nice -n 10 python -B benchmark_cpu.py
nice -n 10 python -B verify.py
```

Reconstruction intentionally creates a small temporary real feature batch used by the bounded benchmark; the benchmark deletes it. Analysis deletes only its own large intermediate source-family matrices and retains a compact baseline. The final process audit must show no surviving owned numerical workers. Output retention is below 50 MB.
